# Folia iPhone 客户端

优先适配 iPhone 16 Pro，最低系统 iOS 17。保留原来的 React 界面、歌词解析和动画，让背景铺满屏幕，按系统安全区域和键盘可见区域安排交互内容，用 Swift / AVPlayer 管理音频、文件、后台队列及系统媒体控制。界面资源随应用安装，本地播放不依赖网页服务器。

## 构建与安装

需要 Node.js 24+、Xcode 和 iOS SDK。

```sh
npm ci
npm run build:ios
npm run ios:open
```

在 Xcode 的 App target 中选择自己的签名团队和 iPhone，运行即可安装。模拟器可用 `npm run ios:simulator` 构建。

导出签名 IPA：

```sh
FOLIA_TEAM_ID=你的团队ID npm run ios:archive
FOLIA_EXPORT_OPTIONS=/绝对路径/ExportOptions.plist npm run ios:export
```

ExportOptions 使用 Xcode Organizer 为对应分发方式生成的配置。开发签名只能用于描述文件包含的设备，且会过期；不能把开发 IPA 当作所有 iPhone 均可直接安装的通用包。仓库不保存证书、描述文件或账户信息。

## 使用与适配

- 本地音乐入口使用系统“文件”选择器，支持多选；文件复制到应用的 Documents/Library，重启后仍可离线读取。
- 竖屏重新排列搜索和导航，横屏保留可滚动设置面板；UIKit 避开灵动岛、圆角及底部手势区域，输入时为键盘让出空间。
- 原来的 15 种歌词样式、主题和歌词解析逻辑继续复用；原生播放进度驱动歌词时钟。
- 本地及已解析的 Navidrome 队列可由原生播放器在后台续播，接入播放/暂停、进度、上一首、下一首系统控制。
- 默认跟随系统减少动态效果，渲染上限 60 fps；这不等于所有设备、所有复杂 3D 模式都已达到稳定 60 fps。

## 在线平台配置

网易云在没有配置外部服务时使用 iOS 直连：仅请求官方 `https://music.163.com`，本地生成二维码，复用已锁定版本的开源 API 中不依赖 Node 的请求与响应转换。已验证真实服务的二维码生成、再次生成、等待扫码状态，以及匿名搜索。账号本人仍需扫码并确认，尚未替用户完成账号授权。

QQ 和酷狗仍需要原项目对应的服务端；构建前在不提交到 Git 的 `.env.local` 配置 `VITE_QQ_API_BASE`、`VITE_KUGOU_API_BASE`，使用手机可以访问的完整 HTTPS 地址。`VITE_NETEASE_API_BASE` 可选，配置后覆盖网易云直连。安装包未内置任何第三方公共中转服务器。不要把密码或 API 密钥写入这些变量，前端变量会包含在安装包中。Navidrome 继续通过应用设置配置。

## 尚未覆盖

- 网易云需要 Node、上传处理、反作弊令牌或新版加密的接口尚未全部移植，必要时可配置兼容服务端。
- 尚未解析的在线歌曲地址需要前台 JavaScript；后台队列在这类歌曲处停止，不会擅自跳曲。后续需要原生地址解析或前台预解析和过期刷新。
- 桌面 FFmpeg、DRM 解密、librespot、桌面插件二进制、系统音频捕获不能直接用于 iOS。
- 原生音频尚未接入均衡器、ReplayGain、交叉淡化/automix、FFT/节拍分析；相关能力需要原生 DSP。歌词时间动画保留。
- 本地封面显示在应用内，锁屏封面目前仅支持 HTTPS 图片；后续可导出内嵌封面到原生图片缓存。
- 不支持递归目录导入与自动查找同目录歌词；可用原有入口单独导入歌词文件。重复导入音乐会产生独立条目。删除资料库条目不会删除原文件，可在系统“文件”中管理。
- 真机锁屏、电话中断、蓝牙/AirPlay、iCloud 下载、旧机型长时间发热与耗电仍需设备验收。模拟器通过不代表这些场景已经通过。
