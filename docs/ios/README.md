# Folia for iPhone

[中文说明](README.zh-CN.md)

This port retains Folia's React UI, visualizer registry, lyric parsers, themes, library, settings and Omni providers. Capacitor bundles the UI in the app; it does not load a hosted website. Swift owns document access and AVPlayer playback, queue advancement, interruptions, headset disconnects, and lock-screen commands. The WebView and background fill the complete display; content and touch controls use safe-area insets in both orientations.

## Build and install

Requirements: Node.js 24+, Xcode with iOS SDK, iOS 17+ device. The repository's original AGPL-3.0 license still applies.

```sh
npm ci
npm run build:ios
npm run ios:simulator
npm run ios:open
```

The simulator app is `ios/DerivedData/Build/Products/Debug-iphonesimulator/App.app`. In Xcode, select the App target, choose your signing team and a unique bundle identifier if required, select your iPhone, and Run. No hosted Folia server is required for local playback. Import audio using the Files picker; the app copies it into Documents/Library. Files stay available offline and after relaunch. Deleting a library record does not delete your imported file; manage retained files through Files → On My iPhone → Folia.

For a signed standalone IPA:

```sh
FOLIA_TEAM_ID=YOUR_TEAM_ID npm run ios:archive
FOLIA_EXPORT_OPTIONS=/absolute/path/ExportOptions.plist npm run ios:export
```

Use the export options generated by Xcode Organizer for your distribution method (development, ad hoc, or App Store). Certificates and provisioning profiles are not included. An unsigned archive can be built with `FOLIA_UNSIGNED=1 npm run ios:archive`, but cannot be installed directly on an iPhone. The simulator `.app` is not an IPA.

## Online services

NetEase has an iOS direct transport when `VITE_NETEASE_API_BASE` is absent. It calls only `https://music.163.com`, generates web QR images locally with the upstream chain ID and a persistent installation/session identity, preserves session cookies, and reuses the pinned upstream package's pure request/response modules at build time. QR creation, repeat creation, waiting-state polling, and anonymous search were checked against the real service. A complete account login still requires the account owner to scan and approve; that was not performed by the agent. Modules that require Node, anti-cheat token generation, upload processing or newer encryption are not automatically included. A separately configured compatible backend remains an option for those operations.

QQ and Kugou retain their original adapters and require their corresponding backend endpoints. Configure `VITE_QQ_API_BASE` and `VITE_KUGOU_API_BASE` in ignored `.env.local` before building. An optional `VITE_NETEASE_API_BASE` overrides the direct transport. These must be absolute HTTPS URLs accessible from the phone. No arbitrary public relay is bundled. Never put passwords or API secrets into Vite variables: they are bundled into the app. Native HTTP avoids WebView CORS restrictions; it does not supply account entitlements.

Navidrome is configured through the existing settings; use an HTTPS server with a valid certificate.

## Platform boundaries

- Local music and Navidrome queues are resolved ahead of time, allowing native advancement while WebKit is suspended. Provider URLs that need JavaScript resolution cannot be generated while suspended; online-radio/unresolved online queue advancement still needs the foreground. A queue stops at an unresolved boundary rather than silently skipping tracks.
- The native engine supports iOS AVFoundation codecs (including AAC, MP3, ALAC, PCM and supported FLAC). Desktop FFmpeg fallback, DRM decryption, Spotify librespot, Electron-only providers, desktop wallpaper, system-audio capture and desktop extension binaries are unavailable. Unsupported streams report an error; no fake success path is used.
- Native playback does not pass through Web Audio: desktop EQ, ReplayGain processing, beat/stem analysis, audio-reactive FFT effects and crossfade/automix are not implemented. Timed lyric animations still use the original clock/renderers. A native audio DSP implementation is needed for these features.
- Native lock-screen metadata supports title/artist/album/progress and HTTPS artwork. Embedded/local artwork remains visible in Folia but is not yet exported to lock-screen artwork.
- Local embedded lyrics and imported lyric files use the original parser. The native audio picker imports individual/multiple music files; recursive folder scanning and automatic sibling lyric discovery are not available. Use the existing lyric-import action for sidecar files.
- Local files are retained in the sandbox; the original app's song/playlist metadata remains in its persistent database. Reimporting the same file currently creates a separate catalogue entry.
- Transfer of WebView cached audio to native playback is chunked; a single cached item is limited to 512 MiB. Native temporary copies are removed on next app launch.
- No universal claim of 60 fps: the runtime caps drawing at 60 fps, respects system reduced-motion by default, and pauses naturally when WebKit is suspended. Complex 3D modes still require profiling on physical older devices.

See [VALIDATION.md](VALIDATION.md) for the exact checks performed and remaining device-only checks. Never treat a mock-browser playback test as proof of native background audio.

## Reproduce validation

```sh
npm run typecheck
npm run test:unit -- test/unit/ios test/unit/playback/songAudioSource.test.ts
npm run test:ios
# Build resources first; the native test uses the bundled production worker.
npm run build:ios
FOLIA_SIMULATOR_ID=YOUR_IPHONE_SIMULATOR_UUID npm run test:ios:native
```

The native runner backgrounds the simulator test host using Settings. It operates on generated test audio, not your music. See the validation record for device-only checks that remain.

## Immersive playback and clear materials (build 4)

The lyric scene fills the display; only interactive chrome respects safe areas. Tap player background to hide or restore transport controls. iOS 26+ uses a native UIKit `UIGlassEffect(style: .clear)` transport; earlier systems use ultra-thin system material. Advanced controls and settings retain Folia React panels with translucent backgrounds and blur (12% control tint, 22% settings tint). These panels are not UIKit Liquid Glass. Reduced-transparency preferences use a more opaque fallback. Native and web transport controls no longer overlap; panel volume rows and tab touch areas have consistent sizes.

## iPhone settings cleanup (build 5)

Native iOS omits keyboard/window/cursor settings, web transport layout and old track-card controls, OBS/stage capture, desktop renderer workarounds and unavailable Web Audio processing. The same availability policy excludes these targets from settings search/navigation. Language, appearance, lyrics, queues, performance, Navidrome and configuration backup remain. Tutorial hosts, lightbulb/hover hints, loop-button guide notices and startup prompts are suppressed on iOS. Help keeps version/community information. Desktop behavior is retained.
